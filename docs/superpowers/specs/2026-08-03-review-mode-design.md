# 誤答の蓄積と復習モード 設計

作成日: 2026-08-03

## 背景

現状、解答結果は問題単位ではどこにも永続化されない。localStorage に残るのは
`cc-diagnosis-progress` のステージ単位の記録（`cleared` / `bestScore` / `attempts` /
`lastAttemptAt`）だけで、どの問題を間違えたかは残らない。

誤答レビューは `sessionStorage` の一時データとして結果画面に渡しているため、
タブを閉じた時点で消える。学習者は「間違えた問題をあとで見返す」ことができず、
「どの領域が弱いか」も 20 ステージのスコアからしか読み取れない。

自習用途では、この損失が挑戦のたびに確実に発生する。

## スコープ

### やること

1. 問題 ID 単位の誤答履歴を localStorage に永続化する
2. 誤答履歴のある問題だけを出題する「復習モード」を追加する
3. ダッシュボードの各ステージセルに、未復習の誤答数バッジを表示する

### やらないこと

- 中断・再開（進行中セッションの保存）
- 全問題の正誤履歴・正答率分析
- 進捗のエクスポート／インポート
- ダークモード、キーボード操作

### 変わらないこと

- ゲート構造（10 問・8 問正解で合格・次レベル開放）
- サーバーなし、localStorage のみ、外部送信なし

**復習モードはゲートに一切影響しない。** 復習は練習、通常ステージは実力判定、
と役割を分ける。誤答問題は一度見た問題であり、これで合格できるとゲートが形骸化する。

## データ設計

### 保存先

```text
localStorage['cc-diagnosis-progress']  … 既存。ゲート判定用。変更なし
localStorage['cc-diagnosis-review']    … 新規。誤答履歴
```

既存の進捗とは別キーにする。理由は 3 つ。

- 既存の `normalizeProgress` は壊れたデータを黙って初期状態に戻す設計で、
  同居させると片方の破損で両方失われる
- ゲート判定は誤答履歴を必要とせず、逆も同様。依存のないものを一つの構造に押し込まない
- 誤答履歴が肥大しても既存の進捗保存に影響しない

### 構造

```json
{
  "version": 1,
  "items": {
    "security-046": {
      "domain": "security-permissions",
      "level": "advanced",
      "wrongCount": 2,
      "lastResult": "wrong",
      "lastAnsweredAt": "2026-08-03T10:00:00.000Z"
    }
  }
}
```

各エントリが `domain` / `level` を持つのは、バッジ集計とステージ別復習で
247 問の JSON を読まずに済ませるため。ダッシュボードは `data/questions/*.json` を
fetch せずに描画できる。

### 記録ルール

| 状況 | 動作 |
|---|---|
| 誤答した | エントリを作成、または `wrongCount` を +1。`lastResult` を `"wrong"` に |
| 復習モードで正解した | `lastResult` を `"correct"` に。**エントリは消さない** |
| 通常ステージで正解した（既存エントリあり） | `lastResult` を `"correct"` に |
| 通常ステージで正解した（エントリなし） | **何もしない** |

正答のみの問題を記録しないことで、データ量を小さく保つ。

### 「未復習の誤答」の定義

`lastResult === "wrong"` のエントリ。これがバッジの数字であり、復習モードの出題対象。

正解するとバッジから外れるが、`wrongCount` は残るため「以前つまずいた問題」を
将来利用する余地を残す。

### 壊れたデータの扱い

形が不正なエントリは黙って捨てる。ただし**捨てるのはエントリ単位**で、
1 件壊れても全体は初期化しない（誤答履歴は積み上げた価値があるため）。
`version` が一致しない場合のみ全体を初期化する。

### 問題データとの不整合

問題が削除・ID 変更されると、履歴に存在しない問題 ID が残る。
復習モードは出題時に実在する問題だけを対象とし、バッジ集計も同様に扱う。
孤児エントリは害がないため削除しない。

## 復習モードの動作

### 導線

- ダッシュボードのステージセルのバッジ（`⚠3`）をクリック → そのステージの復習へ
- 進捗カードの下の「すべての誤答を復習（N 問）」ボタン → 全領域まとめて復習

URL は既存の `quiz.html` を流用する。

```text
quiz.html?mode=review&domain=security-permissions&level=advanced
quiz.html?mode=review
```

### 出題

- 対象: `lastResult === "wrong"` かつ実在する問題
  （ステージ指定時はその `domain` / `level` に絞る）
- 問題数: 対象の全件。ただし上限 20 問（超過分はランダム抽出）
- 選択肢シャッフル・出題順シャッフルは通常ステージと同じ

### 進行中の表示

通常ステージとほぼ同じ画面。ステージラベルを `復習 / 安全性・権限管理 上級` の形式にし、
「合格ライン 8 問」の文言は出さない。

### 終了時

- 誤答履歴を更新する（正解した問題は `lastResult: "correct"`）
- **`cc-diagnosis-progress` は一切更新しない**（`recordAttempt` を呼ばない）
- 既存の `result.html` に遷移する（`sessionStorage` 経由で結果を渡す既存の仕組みを流用し、
  結果データに復習モードであることを示すフラグを持たせる）。
  合格／不合格の判定は出さず、`8 / 12 問正解` と誤答レビューのみ表示。
  学習アドバイスと「次のレベルが開放されました」の案内は表示しない
- 導線は「もう一度復習する」「ダッシュボードに戻る」

### 対象が 0 問のとき

バッジが出ないため通常は到達しないが、URL 直打ちや別タブで復習を完了した後には
起こりうる。その場合はダッシュボードへ戻す。

### 実装上の要点

現在の `js/quiz-page.js` は 200 行で、URL パース・出題・採点・保存・画面遷移を
すべて持っている。復習モードを条件分岐で足すと見通しが悪くなるため、
モード差分（出題対象の決定、終了時の保存処理、ラベル）を切り出し、
共通の出題ループはそのまま使う。

全領域復習では 5 つの JSON を並行 fetch する。

## ダッシュボードのバッジ

```text
┌──────────────┐
│  ✅   上級    │   ← 既存: マーク / レベル名 / スコア
│    9/10  ⚠3  │   ← ⚠3 が追加分（クリックで復習へ）
└──────────────┘
```

### 表示ルール

- 未復習誤答が 0 件のセルには何も出さない
- 未開放（🔒）のセルにも表示する。ロック中のステージに誤答が付くことは通常ないが、
  復習はゲートに影響しないため塞ぐ理由がない
- バッジは合格状態（✅ / ▶ / 🔒）とは独立。合格済みでも誤答が残れば `⚠` が付く

### クリック挙動

セル全体は従来どおりそのステージへの挑戦リンク。バッジだけは復習モードへのリンクとし、
セルのリンクとは分離する。

実装は、セルを `<a>` から `<div>` + 内部リンク 2 つに変える方式を採る。
入れ子リンクは HTML として不正で、スクリーンリーダーの挙動も壊れるため、
`preventDefault` で遷移先を差し替える方式は採らない。

### 全体復習ボタン

進捗カードの下に配置。未復習誤答が 1 件以上あるときだけ表示する。

```text
[ すべての誤答を復習（12問） ]
```

### アクセシビリティ

`aria-label` は `安全性・権限管理 上級の誤答3問を復習` のように明示する
（既存セルと同じ方針）。色だけに頼らず `⚠` と数字で示す。

### 印刷

バッジは印刷時も表示する（誤答の所在は紙でも有用なため）。

## エラー処理

誤答履歴はゲートの前提ではないため、既存の進捗保存より一段軽く扱う。

- 保存に失敗しても**挑戦の完了自体はブロックしない**。既存の `showSaveFailure` は
  進捗とステージ結果の保存失敗時のみ発火し、誤答履歴の失敗では結果画面への遷移を止めない
- トップページの既存ストレージ注記（「進捗を保存できません」）が誤答履歴にも当てはまるため、
  新しい警告文は追加しない
- 復習モードで履歴を更新できなかった場合、正解した問題がバッジに残り続ける。
  これは「保存できない環境では何も残らない」という既存の挙動と一貫しており、追加説明は不要

問題データの fetch 失敗は既存の `showLoadError` を流用する。
全領域復習で一部の JSON だけ失敗した場合は、**取得できた領域だけで出題**する
（全滅時のみエラー表示）。

## テスト

既存の `node --test` に純粋関数のテストを追加する。DOM を持たない設計を維持する。

新規モジュール `js/review.js` に対して:

- `recordAnswers` — 誤答で `wrongCount` が増える／正解で `lastResult` が `correct` になる／
  未登録の問題の正解は記録されない
- `normalizeReview` — 壊れたエントリだけが捨てられ、正常なエントリは残る／
  `version` 不一致は全体を初期化
- `selectReviewQuestions` — `lastResult === "wrong"` だけが対象／
  `domain`・`level` での絞り込み／実在しない問題 ID の除外／20 問上限
- `countUnreviewedByStage` — ステージ別集計がバッジの数字と一致する

既存テスト（`progress.test.js` 等）は変更しない。

**「復習モードが `cc-diagnosis-progress` を変更しない」ことをテストで固定する。**
ここが壊れるとゲートの意味が失われるため、最も重要な不変条件である。
