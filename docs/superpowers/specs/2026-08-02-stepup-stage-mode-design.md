# ステップアップ式問題集への転換 設計書

作成日: 2026-08-02

## 背景と目的

現在のアプリは「1回50問を通しで解き、領域ごとの正答率から4段階のレベルを判定する」一発診断ツールである。
実力を測ることはできるが、初心者が上級者へ段階的に成長するための構造がない。診断結果を得たあと、
次に何をすべきかが示されず、反復して力をつける導線もない。

本設計では、アプリを**ステップアップ式の問題集**へ転換する。前のレベルに合格した領域だけが
次のレベルに挑戦できるゲート構造を導入し、学習の道筋と達成感を与える。

## スコープ

対象は出題・判定・進捗管理の仕組みの変更である。問題データ（5領域 × 4レベル × 各10問 = 200問）は
そのまま流用し、内容の追加・改訂は行わない。

## 中核となる概念

### ステージ

5領域 × 4レベル = **20ステージ**。各ステージは、その領域・そのレベルの問題10問からなる独立した
チャレンジである。アプリの利用単位は「1回の診断（50問）」から「1ステージ（10問）」に変わる。

領域とレベルは既存の定義を踏襲する。

- 領域: `basic-operations` / `feature-usage` / `prompt-design` / `security-permissions` / `token-efficiency`
- レベル: `beginner` / `intermediate` / `advanced` / `expert`

### 合格ライン

**10問中8問以上の正解**でそのステージに合格する。7問以下は不合格。

各レベルのプール10問をすべて出題するため、80%という基準が整数で素直に決まる。出題ごとに
問題の順序と選択肢の順序はシャッフルする。

### ゲート構造

ある領域の中では、前のレベルに合格しないと次のレベルが開かない。

- 初級は常に挑戦可能
- 中級は初級に合格していれば挑戦可能
- 上級は中級に合格していれば挑戦可能
- エキスパートは上級に合格していれば挑戦可能

領域どうしは独立している。「基本操作は上級に到達、セキュリティはまだ初級」という状態が
自然に表現され、5本のトラックが並行して進む。

ステージの状態は3つ。

| 状態 | 意味 | 操作 |
|------|------|------|
| `cleared` | 合格済み | 再挑戦できる |
| `available` | 挑戦可能（前レベル合格済み、または初級） | 挑戦できる |
| `locked` | 前レベル未合格 | 挑戦できない |

合格済みステージの再挑戦で不合格になっても、`cleared` は `false` に戻さない。一度得た到達は
剥奪しない。再挑戦を許すのは「一度通ったが忘れた」状態を利用者自身が潰せるようにするためである。

## データモデル

### 進捗データ

`localStorage` のキー `cc-diagnosis-progress` に以下の構造で保存する。

```json
{
  "version": 1,
  "domains": {
    "basic-operations": {
      "beginner":     { "cleared": true,  "bestScore": 9, "attempts": 2, "lastAttemptAt": "2026-08-02T10:00:00.000Z" },
      "intermediate": { "cleared": false, "bestScore": 6, "attempts": 1, "lastAttemptAt": "2026-08-02T10:20:00.000Z" },
      "advanced":     null,
      "expert":       null
    }
  }
}
```

- 未挑戦のレベルは `null`
- `bestScore` と `attempts`、`lastAttemptAt` は表示用の付随情報であり、ゲートの判定には関与しない
- ロック状態はデータに保存せず、`cleared` から都度導出する。状態の二重管理を避けるため
- `version` は、将来プールを拡張して出題方式を変える際の移行余地として持たせる

進捗の真実は「どのステージに合格したか」だけである。

### 旧データの扱い

既存の `cc-diagnosis-result`（最新1件の診断結果）は読み書きしない。放置する。
旧形式からのマイグレーションは行わない。正答率ベースの4段階判定と80%ゲートは基準が異なり、
変換ルールに恣意性が残るうえ、移行コードが将来の負債になるためである。

既存利用者は進捗ゼロから再スタートとなるが、「実際に各ステージを解いて合格した」という事実にこそ
意味がある設計であり、過去の推定値を引き継ぐ価値は低い。

### 問題データ

`data/questions/*.json` は変更しない。各ファイルは `domain` / `domainLabel` / `questions` を持ち、
各問題は `id` / `level` / `question` / `choices` / `correctIndex` / `explanation` を持つ。

## 画面構成

3画面構成（`index.html` / `quiz.html` / `result.html`）は維持し、役割を入れ替える。

### `index.html` — 進捗ダッシュボード

5行 × 4列のグリッド。行が領域、列がレベル。

```
                初級    中級    上級   エキスパート
基本操作・CLI     ✅      ▶      🔒      🔒
機能活用          ✅      ✅      ▶      🔒
プロンプト設計    ▶      🔒      🔒      🔒
安全性・権限      ✅      ▶      🔒      🔒
トークン効率      ▶      🔒      🔒      🔒
```

- ✅ 合格済み — クリックで再挑戦
- ▶ 挑戦可能 — クリックでステージ開始
- 🔒 ロック — クリック不可。「中級に合格すると開放」とツールチップで理由を示す

各セルには最高スコア（`9/10`）を小さく添える。未挑戦のセルにはスコアを表示しない。

### `quiz.html` — ステージ挑戦

対象ステージはURLクエリで受け取る。

```
quiz.html?domain=basic-operations&level=intermediate
```

ヘッダーに「基本操作・CLI / 中級」と現在地を表示し、10問を1問ずつ進行する。
解答を選ぶと即座に正誤をフィードバックする既存の挙動は維持する。

該当領域のJSONのみを `fetch` する。全5ファイルを読む必要がなくなり、初期ロードが軽くなる。

**進捗の書き込みは解答完了時点で行う**。結果画面の到達時ではない。結果画面をリロードしても
`attempts` が二重に加算されないようにするためである。

### `result.html` — ステージ結果

- `8/10 合格！` または `6/10 不合格` を大きく表示
- 合格時: 「次のレベル（上級）が開放されました」と、開放されたステージへの導線
- 不合格時: 「もう一度挑戦」ボタン
- どちらの場合も、間違えた問題の正解と解説を一覧表示（既存実装を流用）
- 「ダッシュボードに戻る」を常に置く

### 画面間のデータ受け渡し

出題内容と解答は `sessionStorage` で quiz → result に渡す（現行と同様の方式）。

## モジュール構成

既存のファイル分割は素直なので、その境界を保ったまま責務を入れ替える。

### 新規: `js/progress.js`

進捗の読み書きとステージ状態の導出を担う。このアプリの中核ロジックであり、UIから完全に独立させる。

```js
loadProgress()                                 // 保存済み進捗を返す。無ければ空の初期状態
recordAttempt(progress, domain, level, score)  // 純関数。新しい進捗オブジェクトを返す
saveProgress(progress)
getStageStatus(progress, domain, level)        // 'cleared' | 'available' | 'locked'
isPassed(score)                                // score >= 8
buildDashboard(progress, domains)              // 全20ステージの状態一覧を返す
```

`recordAttempt` を純関数にすることで、テストを保存機構から切り離す。
`storage.js` は保存の入れ物に徹し、進捗の意味づけは `progress.js` が持つ。

### 変更: `js/level-judge.js`

正答率による4段階判定（`judgeDomainLevel` / `judgeAllLevels`）は役目を終えるため削除する。
`LEVELS` と `LEVEL_LABELS` は全画面で使うので残す。実質「レベルの語彙を定義するモジュール」に縮小する。

### 変更: `js/quiz-engine.js`

- `selectQuestions(domainData, level, count, rng)` — 指定した領域・レベルのプールから `count` 問を
  シャッフルして抽出し、各問題の選択肢もシャッフルする。`count` は10とし、プールが10問ちょうどなら
  実質的に全問が順不同で出題される。プールが11問以上ある場合はそこからランダムに10問を抽出する
  （将来のプール拡張への備え）
- `buildQuiz` — 全領域ぶんを組み立てる関数。不要になるため削除
- `gradeAnswers` — 領域ごとの集計。不要になるため削除
- `scoreStage(questions, answers)` — 新規。単一ステージの正解数を返す
- `shuffle` / `shuffleChoices` / `collectWrongAnswers` — そのまま維持

### 変更: `js/storage.js`

進捗用のキーを追加する。既存の例外安全な設計（`localStorage` 失敗時に `sessionStorage` へ退避）を踏襲する。

### 変更: `js/top-page.js`

ダッシュボードのレンダリング。20セルの状態表示とクリックハンドリングを担う。

### 変更: `js/quiz-page.js`

URLクエリからステージを特定し、該当領域のJSONを `fetch` する。
解答完了時に `recordAttempt` → `saveProgress` を実行する。

### 変更: `js/result-page.js`

合否表示と、次ステージ開放の案内を担う。

### 変更: `js/report-content.js`

現在の「レベル別の改善アドバイス」20件はそのまま活かす。ステージ不合格時に
「このレベルの学習アドバイス」として表示する用途に転用する。
関数名を `getImprovementSuggestion` から `getStudyAdvice(domain, level)` に変更し、テキストは変えない。

## エラー処理とエッジケース

**不正なURLパラメータ** — 存在しない領域・レベルが指定された場合、またはパラメータが無い場合は
トップページへリダイレクトする。手打ちURLや古いブックマークを想定する。

**ロック中ステージへの直接アクセス** — URL直打ちでロック中のステージに入られた場合もトップへ
リダイレクトする。厳密な防御ではないが、ゲート構造が意味を持つよう最低限の一貫性を保つ。

**問題データの取得失敗** — `fetch` 失敗時（`file://` で開いた、ファイル欠損など）はエラーメッセージを
画面に表示し、簡易サーバー経由で開く旨を併記する。現行の挙動を踏襲する。

**プールが10問未満** — `selectQuestions` が明示的にエラーを投げる現在の設計を維持する。
データ不備を黙って通さないため。`tests/question-data.test.js` が先に検知する。

**localStorage が使えない環境** — プライベートブラウジング等。既存のフォールバック思想を踏襲し
`sessionStorage` に退避する。それも失敗する場合は進捗がメモリ上のみとなるため、その旨を
ダッシュボードに注記表示する。ゲート方式では進捗の永続性が体験の前提になるため、
黙って失われることは避ける。

**進捗データの破損** — JSONパース失敗、未知の `version`、構造の破損を検知した場合は、
破損データを捨てて初期状態から開始する。ゲート構造は「合格した事実」の積み重ねであり、
部分的な復旧を試みるより初期化のほうが安全で予測可能である。

**sessionStorage 経由の受け渡しが欠落** — `result.html` を直接開いた、あるいはリロードで
データが失われた場合はダッシュボードへ誘導する。進捗自体は quiz 完了時点で確定済みのため、
結果画面を見逃しても記録は失われない。

## テスト方針

Node の `node --test` によるユニットテストを継続する。`progress.js` は純関数中心のため
DOM 非依存でテストできる。

### 新規: `tests/progress.test.js`

重点は3点。

1. **ゲートの開閉** — 初級は常に開放される。中級は初級合格後にのみ開放される。飛び級はできない
2. **合格ラインの境界** — 7問正解は不合格、8問正解は合格
3. **合格済みステージの非降格** — 再挑戦で不合格になっても `cleared` が維持される

### 改訂: `tests/quiz-engine.test.js`

新しい `selectQuestions`（単一レベル10問）と `scoreStage` に合わせて改訂する。

### 維持: `tests/question-data.test.js`

各レベルに10問以上あることの検証を維持する。あわせて、`id` がドメイン間で一意であること、
`correctIndex` が選択肢の範囲内にあることの検証も維持する。

### 削除: `tests/level-judge.test.js`

判定ロジックの削除に伴い削除する。

### UI

ダッシュボードの表示とステージ遷移は手動確認とする。

## この設計で扱わないこと

以下は本設計のスコープ外とする。将来的に本設計の上へ追加できる。

- **問題プールの拡張** — 各レベル10問を20問に増やし、毎回異なる10問を抽出する方式。
  丸暗記による通過を防げるが、まずは学習サイクルを回せる構造を優先する。
  データ構造を変えずに移行できる
- **連続チャレンジ** — 合格後にそのまま次のレベルへ進む導線。結果画面にボタンを足すだけで実現できる
- **間違えた問題だけの復習モード** — 10問のステージでは全問を解き直すこと自体が復習として機能するため、
  現時点では優先度が低い
- **総合ランク** — 全領域が中級合格で「総合中級」といったバッジ
